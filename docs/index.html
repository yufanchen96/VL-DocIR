Abstract

Vision-based document retrieval has improved rapidly, but current evaluation settings still emphasize short documents and single relevant pages. This leaves an important gap between leaderboard performance and realistic long-document retrieval, where the evidence needed to answer a query may span multiple pages or even multiple documents. We present VL-DocIR, a page-level benchmark for evidence-complete visual long-document retrieval. VL-DocIR is built from 29,641 HTML-born documents rendered into 388,548 page images from Wikipedia, arXiv, PubMed, and SEC proxy statements. It contains 271,760 queries across 23 domains and six evidence structures, covering single-page, within-document multi-page, and cross-document evidence configurations. Evidence annotations are grounded to rendered pages and HTML element identifiers, and queries are filtered with a cleaning pipeline targeting clarity, correctness, closedness, and the absence of explicit layout references. We evaluate leading single-vector and multi-vector visual retrievers together with diagnostic retrieval settings such as document-context scoring, query splitting, reranking, and round-robin ensembles. The strongest evaluated configuration reaches 69.3 nDCGAll@10 and 80.6 RecallAll@10 under structure-balanced Macro evaluation, but source- and evidence-structure breakdowns show that cross-document retrieval remains substantially harder than single-page retrieval, and that document-context scoring is especially helpful for within-document multi-page queries. VL-DocIR exposes these failure modes and provides a more demanding target for visual long-document retrieval.

The VL-DocIR Benchmark

VL-DocIR is a page-level document retrieval benchmark for visually rich long documents. Unlike standard page-level retrieval evaluations that reward retrieving any relevant page, VL-DocIR measures evidence-complete retrieval: a system succeeds only when it retrieves the full set of evidence pages.

The corpus contains 29,641 documents and 388,548 rendered pages from Wikipedia, arXiv, PubMed and SEC proxy statements. The 271,760 queries cover 23 domains and six evidence structures.

The query creation pipeline consists of three stages: evidence-configuration sampling, VLM-based query generation and query cleaning. Evidence element identifiers are resolved to rendered pages and page-relative bounding boxes. Cleaning targets query clarity, answer correctness or plausibility, closedness and the absence of explicit layout references.

Evidence-Complete Evaluation

At evaluation time, a retriever receives only the question and ranks pages from the full corpus. For a query q, let E(q) be its ground-truth evidence-page set and Rk(q) the retrieved top-k page set. Completion requires every page in E(q) to appear in Rk(q).

RecallAll@k(q) = 𝟙[E(q) ⊆ Rk(q)]

nDCGAll@k(q) = RecallAll@k(q) · nDCG@k(q)

Standard nDCG uses binary relevance for the evidence pages. Structure-balanced Macro is the primary aggregate: first average the query scores within each evidence structure, then average the six structure means equally. Micro averages over all queries and is reported as a secondary aggregate. Results are percentages.

Annotation Quality

A stratified human review covers 800 entries across all 24 source × evidence-structure combinations: 50 Cross-Doc entries and 30 entries for each other structure per source. Of these, 746/800 (93.25%) are fully correct; the nominal 95% Wilson interval is 91.3–94.8%. Cross-Doc quality is lower at 88.5%.

The observed issues comprise 13 formulation issues, 20 incorrect evidence sets, 17 sets containing an unnecessary evidence page and four non-presence queries. These rates describe the pre-adjudication audited entries. The benchmark retains limitations from VLM-generated queries, page-level evaluation and its restriction to HTML-born documents. See the paper and dataset card for the audit details.

The current Hub release requires an access request. After access is granted, authenticate locally with hf auth login. For example, the questions collection can be loaded as follows:

from datasets import load_dataset

questions = load_dataset(
    "anonymous-8421/VL-DocIR",
    "questions",
    split="train",
    revision="40a1818110c20e9279bbb4a3b6283ceac2d631ba",
    token=True,
)

The Hub exposes the four JSONL collections as configurations with a split named train. This is the release's packaging label, rather than a separate benchmark training partition. Use (document_id, page_number) as the page key and deduplicate multiple evidence elements on the same page when constructing the evidence-page set.
